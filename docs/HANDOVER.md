# Handover — Smart Sales CRM

**Owner:** WASL Technologies · **Repository:** https://github.com/al-shaghouri-dev/smart-sales-crm ·
**Branch:** `saas/phase-0-1-clean` (do not deploy `main`, which holds the old prototype).

This document tells a hosting / deployment specialist what the system is, what is finished, what must be
provided from outside, and where every procedure is documented.

## 1. What the system is

A multi-tenant sales & customer-messaging CRM (Arabic/English). A **Super Admin** runs the platform
(companies, plans, subscriptions, manual payments, self-registration approval, channel monitoring).
Each **company** has its own team, roles and permissions, branding, unified inbox and messaging channels.
Architecture: one Node.js 22 app (Express 5 API + React 18 frontend + Socket.IO + pg-boss jobs) and
PostgreSQL 16 with Row Level Security. Details: ARCHITECTURE.md.

## 6. Security essentials

- The app must connect as the **restricted role** (NOBYPASSRLS); `prepare-database.js` enforces it.
- Keep `APP_ENCRYPTION_KEYS` in a password manager; rotate with `npm run secrets:rotate`.
- Never expose PostgreSQL publicly; keep the app port bound to localhost behind the proxy.
- Remove `BOOTSTRAP_ADMIN_*` after the first sign-in.
- `NODE_ENV=production` enforces https URLs for channels, refuses the test provider and missing keys.

## 8. Development

`npm install`, local PostgreSQL (`docker compose up -d` for the dev database), `.env` with `NODE_ENV=development`,
`npm run migrate`, `npm run dev` (API, port 3000) + `npm run dev:web` (Vite, port 5173), `npm test`.
Conventions: every schema change is a new migration; every server error code and audit action needs
Arabic and English labels (`web/src/locales`), enforced by `test/web/i18n.test.mjs`.
